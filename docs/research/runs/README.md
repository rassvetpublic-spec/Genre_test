# Research Radar run records

Store concise, durable Research Radar run summaries here when a run produces
project-relevant state changes or evidence.

Use a sortable date/run identity in the filename. A run record should capture
scope, search horizon, material source revisions when known, new/changed/blocked
candidates, test or retest obligations, state changes, and unresolved follow-up.

Do not commit raw search-result dumps, copied webpages, temporary prompts, or
unfiltered model output.

Canonical mutable continuation state remains in `../data/RESEARCH_STATE.json`.
