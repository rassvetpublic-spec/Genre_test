# Genre_test — русская дорожная карта проекта

## Что это за проект

**Genre_test** развивается из анализатора жанра и музыкального профиля в локальный **суперкомбайн по доводке генеративных песен до студийного уровня**.

Главная идея проста: на входе может быть готовая генеративная песня, отдельные стемы или каталог треков. На выходе проект должен уметь не только сказать, «что это за музыка», но и помочь довести материал до состояния, когда его можно спокойно слушать, сравнивать, мастерить, подписывать тегами и готовить к выпуску.

Целевой путь:

```text
Исходная песня / стемы
  -> Анализ
  -> Каталог и поиск похожего
  -> Техническая проверка
  -> Разделение на стемы при необходимости
  -> Исправление слышимых генеративных артефактов
  -> Исправление вокала
  -> Исправление и постобработка стемов
  -> Сведение / мастеринг
  -> Синхронное A/B/X сравнение вариантов
  -> Проверка и исправление тегов
  -> Финальная проверка
  -> Готовый мастер и пакет файлов
```

**Главная цель:** убрать слышимые дефекты генерации, нестабильность, «дешёвый цифровой налёт», слабые места сведения и мастеринга, сохранив исходник нетронутым и ведя историю всех обработок.

Проект не строится вокруг обмана систем определения происхождения аудио. Критерий качества — **как реально звучит музыка**, а не оценка стороннего детектора.

# Что уже работает

## Стабильная база v0.4.0

На текущем этапе уже работают:

- локальный анализ музыкальных файлов;
- определение жанрового направления и широкого семейства жанров;
- дополнительный семантический анализ содержимого трека;
- BPM, тональность и режим;
- несколько режимов вывода результата;
- история анализов;
- Validation и повторная проверка результатов;
- сравнение результатов между версиями анализатора;
- обработка каталогов;
- Safe Stop — корректная остановка анализа без повреждения уже полученных результатов;
- GPU-ускорение;
- FFmpeg fallback для расширенной поддержки форматов;
- живой монитор ресурсов: CPU, RAM, GPU, VRAM, температура, питание и память текущего процесса.

На рабочем компьютере подтверждена стабильная работа с RTX 5070 Ti и современным CUDA-стеком. В тестовом прогоне 20 треков были обработаны без ошибок примерно за минуту с корректной безопасной остановкой.

# Общие правила проекта

1. Исходный аудиофайл не изменяется.
2. Все исправления, стемы, миксы и мастера создаются как новые производные файлы.
3. Каждый производный файл должен знать, из какого исходника он получен и каким способом.
4. Тяжёлые модели должны быть необязательными: если какой-то модуль не установлен, базовый анализ всё равно работает.
5. Разные версии моделей и индексов нельзя молча смешивать.
6. Любое автоматическое исправление должно уметь сказать: «уверен», «сомневаюсь» или «не знаю».
7. Красивое текстовое описание не считается новым доказательством. Сначала измерение, потом вывод, потом понятное описание.
8. Разрушающие операции с файлами и тегами сначала показывают план изменений и должны иметь возможность отката.
9. Перед релизом обязательны тесты, ручная проверка и MTD.

# FAR TODO — идеи на дальнюю перспективу

Эти функции полезны, но **не должны тормозить ближайшие версии**. Они переходят в активную разработку только после того, как можно показать источник данных, тестовый набор, измерить точность и заранее определить поведение при ошибке.

## 1. Богатый вокальный профиль

Желаемые признаки:

- язык вокала;
- ясность дикции;
- вероятность присутствия вокала;
- lead/background;
- singing / rap / spoken / voiceover;
- низкий/средний/высокий регистр;
- хриплый, воздушный, яркий, тёмный тембр;
- разговорная, агрессивная, интимная, сдержанная подача;
- сухой/мокрый вокал;
- близкий/далёкий микрофонный образ;
- центр/ширина вокала.

Почему FAR: для честных выводов нужны специальные вокальные модели и отдельная проверка, а не просто красивые ярлыки.

## 2. Детальный ритм, ударные и бас

Желаемые признаки:

- активность kick/snare/clap/hat;
- плотность hi-hat rolls;
- синкопы;
- loose/off-grid timing;
- сила грува;
- 808/sub presence;
- sliding bass;
- плотность транзиентов;
- main beat и secondary groove;
- halftime/doubletime и другие ритмические режимы.

Путь к реализации: beat tracking + onset-статистика + при необходимости разделение стемов + ручные эталоны.

## 3. Полный perceptual production/mix profile

Желаемые признаки:

- polished/raw;
- ширина стерео;
- стабильность центра;
- совместимость с моно;
- punch транзиентов;
- характер насыщения;
- macro/micro dynamics;
- bright/dark;
- глубина вокала;
- dry/wet;
- громкость, True Peak и crest factor.

Объективные измерения будут появляться раньше. Слова вроде «дорогой», «сырой», «панчевый», «аналоговый» публикуются только после калибровки.

## 4. Определение характера обработки

Допустимый будущий формат:

```text
Похоже по характеру на:
  жёсткое ограничение пиков
  сильное насыщение
  усиление атаки транзиентов
```

Жёсткое правило: нельзя утверждать конкретный плагин, бренд или цепочку, если этого нет в реальных метаданных проекта.

## 5. Творческие рекомендации

- предложить beat switch;
- предложить подъём темпа;
- предложить контраст в bridge/drop;
- предложить инструмент или transition FX;
- выдавать подсказки для следующей генерации.

Этот слой всегда отделён от фактического анализа:

```text
Только анализ

```

Пример:

```text
Эпоха звучания: 2020-е
Уверенность: средняя
```

Это оценка **эстетики продакшна**, а не фактического года выпуска.

## 7. Инструменты и мотивы

- главный гармонический мотив;

# Когда FAR TODO может стать активной задачей

Перед переносом любой далёкой идеи в активную разработку нужно:

1. выбрать конкретный источник данных или модель;
2. проверить лицензию и происхождение;
3. описать версионированный формат результата;
4. определить уверенность и состояние «неизвестно»;
5. собрать вручную проверенные примеры;
6. измерить точность и повторяемость;
7. добавить regression-тесты;
8. описать типичные ошибки;
9. завести отдельную задачу разработки;
10. не мержить без MTD.

# Конечная картина

Genre_test должен стать одним локальным рабочим местом для доводки генеративной песни:

```text
получил трек
 -> понял, что в нём происходит
 -> нашёл похожие референсы
 -> увидел технические проблемы
 -> при необходимости разобрал на стемы
 -> исправил слышимые дефекты
 -> привёл в порядок вокал и отдельные части
 -> собрал несколько вариантов
 -> сравнил их честно на одной громкости
 -> сделал профессиональный мастер
 -> проверил моно, кодеки, пики и ударные
 -> проверил и исправил теги
 -> получил готовый WAV 24-bit / 48 kHz и отчёт
```

Идеальный пользовательский результат должен выглядеть не как набор разрозненных утилит, а как понятный маршрут от сырого генеративного файла до аккуратного студийного мастера.
